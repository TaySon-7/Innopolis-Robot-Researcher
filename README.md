# Robot Researcher

Воспроизводимый стенд для задачи DID Hack «Автономный ИИ-исследователь на
роботе-платформе».

В проект входят:

- ROS 2 Jazzy и Gazebo Sim Harmonic в Docker;
- официальный TurtleBot3 Burger в шестиугольной арене с девятью столбами;
- судья со сценариями `easy`, `medium` и `hard`;
- навигация A*, автономный агент, адаптация и журнал решений;
- React-панель с большой картой, лидаром, маршрутом и управлением роботом.

На macOS Gazebo работает headless: физика, лидар, одометрия и управление
полностью активны, но отдельное окно Gazebo не требуется.

## Быстрый старт

Нужен запущенный Docker Desktop.

```bash
make ui
```

Команда собирает и запускает оба контейнера, ждёт готовности сервисов и открывает
[http://localhost:8080](http://localhost:8080). Повторные сборки используют
Docker-кэш.

Для проверки ROS-стенда:

```bash
make check
```

## React-панель

Панель показывает данные в мировой системе координат, поэтому арена остаётся на
месте, а перемещаются Burger, его след, маршрут и лучи лидара.

В интерфейсе доступны:

- увеличенная шестиугольная карта, все девять столбов и сырые возвраты `/scan`;
- маршрут агента, изученная карта стоимости и переключатель скрытой истины;
- клик по карте для движения и `Shift+клик` для поиска образца;
- состояние навигации, перепланирования, оценка возврата и признаки аномалий;
- журнал гипотез, выводов и решений агента, а также события судьи;
- батарея, сигнал датчика, координаты, курс, скорости, счёт и штрафы;
- автономный запуск, остановка, сбор на текущей позиции и возврат на базу;
- безопасное ручное управление кнопками, стрелками или `W/A/D/X`.

При отпускании кнопки, потере фокуса или разрыве ROS-соединения ручная скорость
сбрасывается. `S`, пробел и красная кнопка выполняют немедленную остановку.
Скорости задаются ползунками напрямую и не накапливаются скачками, как в
`teleop_keyboard`.

## Навигация и агент

Пакет `did_agent` строит сетку стоимости, прокладывает маршрут A* и ведёт Burger
по путевым точкам. Новые препятствия из лидара вызывают перепланирование.

```bash
make goto X=0.55 Y=0.55   # поехать в точку
make auto                 # автономно пройти эпизод
make stop                 # остановить агента
make collect              # собрать образец рядом
make finish               # завершить миссию на базе
```

План можно отправить вручную:

```bash
make plan P='{"plan_id":"p1","subgoals":[{"type":"goto","x":0.5,"y":0.5}]}'
```

## Сценарии

Выбор встроенного сценария:

```bash
SCENARIO=medium make restart       # easy | medium | hard
SCENARIO=hard@7 make restart       # hard с фиксированным seed
```

Сценарии лежат в `ros2_ws/src/did_judge/scenarios`. В них задаются образцы,
грунты с разной ценой движения, опасные зоны и скрытые события.

Генерация и проверка собственного YAML:

```bash
make scenario DIFF=hard SEED=7
make scenario-check FILE=scenarios_custom/hard-7.yaml
```

Сгенерированные файлы сохраняются локально в `scenarios_custom/` и не попадают
в Git.

## Полезные команды

```bash
make ui       # собрать, запустить и открыть React-панель
make topics   # список ROS-топиков
make pose     # одна запись одометрии
make scan     # один кадр лидара
make battery  # заряд
make sensor   # сигнал образца
make score    # состояние судьи
make events   # поток событий судьи
make logs     # журнал симулятора, судьи и агента
make ui-logs  # журнал nginx-контейнера
make shell    # shell внутри ROS-контейнера
make down     # остановить стенд
```

Ручной ROS teleop также остаётся доступен:

```bash
make teleop
```

## Архитектура и порты

Контейнер `sim` содержит Gazebo, ROS 2, судью, агента, HTTP API и `rosbridge`.
Контейнер `dashboard` собирает React через Vite и отдаёт готовую статику через
nginx. Nginx проксирует `/api` к агенту и `/ros` к WebSocket ROS.

- `127.0.0.1:8080` — React-панель;
- `127.0.0.1:8082` — прямой Agent API для разработки;
- `127.0.0.1:9090` — прямой `rosbridge` для диагностики.

Для доступа к панели с другого компьютера:

```bash
DASHBOARD_BIND=0.0.0.0 DASHBOARD_PORT=8080 docker compose up -d --build
```

Для публичного сервера следует поставить HTTPS reverse proxy и ограничить
доступ аутентификацией или VPN.

## Судья

Судья публикует:

- `/did/battery` (`std_msgs/msg/Float32`) — остаток заряда;
- `/did/sample_sensor` (`std_msgs/msg/Float32`) — зашумлённую близость образца;
- `/did/score` (`std_msgs/msg/String`) — состояние и счёт в JSON;
- `/did/events` (`std_msgs/msg/String`) — штрафы и успешные сборы.

Сервисы `/did/collect` и `/did/finish` имеют тип
`std_srvs/srv/Trigger`. Сбор успешен на расстоянии не более 0,30 м.
