# Сравнение custom и Nav2 в Gazebo

`scripts/compare_navigation.py` выполняет один и тот же явный маршрут через
HTTP API на уже запущенном стенде. Перед каждым backend робот пересоздаётся
через выбор сценария, знания агента и показатели судьи сбрасываются. Скрипт
дожидается нового `episode_id`, готовности выбранной навигации, положения на
базе и обновления времени симуляции.

Это проверка навигации, без поиска образцов и LLM. Запустите собранный стенд
с **`LLM=false`**; обычный запуск проекта по умолчанию включает планировщик:

```bash
LLM=false docker compose up --detach --wait
```

При сравнении Nav2 его серверы должны быть запущены и доступны runtime
переключателю. Скрипт ждёт `state.navigation.backend` и `ready: true`; ошибка
готовности сохраняется в результат, backend молча не подменяется.

Сохраните точки в мировой системе `odom` в JSON, например `route.json`:

```json
[[-0.55, -0.55], [0.55, 0.55], [1.70, -0.50], [-2.0, -0.5]]
```

Точки задаёт оператор. Скрипт не читает `/api/truth`, не генерирует цели из
скрытых образцов и не дублирует геометрию арены. Для другой геометрии выбирайте
маршрут по актуальной карте. Последняя точка — обычный `goto`: она не вызывает
завершение миссии и не начисляет награду возврата.

```bash
python3 scripts/compare_navigation.py \
  --llm-disabled --backend both --scenario easy \
  --waypoints route.json --output /tmp/navigation-easy.json
```

Для воспроизводимого сгенерированного сценария используйте `--scenario hard
--seed 7` или `--scenario hard@7`. Для отдельного backend — `--backend custom`
или `--backend nav2`. `--api http://127.0.0.1:8080` позволяет обращаться через
React nginx вместо прямого backend на `:8082`.

Флаг `--llm-disabled` подтверждает способ запуска: HTTP API не позволяет
проверить наличие процесса LLM. Нельзя использовать этот флаг, оставив LLM
включённым: сброс сценария может снова разрешить ему планирование. Сам скрипт
публикует только `stop` и ручные планы, никогда `llm` или `auto`.

По умолчанию на одну точку отведено 90 секунд симуляции и 180 секунд wall clock.
Отдельные лимиты защищают также от приостановленной симуляции. Настройки:
`--goal-timeout`, `--wall-timeout`, `--ready-timeout`, `--poll`,
`--goal-tolerance` (по умолчанию 0.20 м). Каждый HTTP запрос дополнительно
ограничен 15 секундами; текущий запрос может завершиться после общего deadline.

Для каждой точки используется уникальный `plan_id`. `done` другого плана
не считается успехом. После своего `done` скрипт ждёт нового времени судьи
и проверяет ошибку цели по мировой позиции Gazebo. При `failed`, `preempted`,
смене эпизода/контроллера, превышении ошибки или timeout оставшиеся точки этого
backend не выполняются; отправляется `stop`. Второй backend получает независимый
сброс. Если остановка не подтверждена или оператор нажал Ctrl-C, сравнение
дальше не продолжается. Во время теста не управляйте роботом из UI.

JSON содержит маршрут, scenario/seed, лимиты, уникальные планы, результат каждой
точки и суммарные показатели:

- успех маршрута и расстояние от фактической конечной позы до каждой цели;
- время симуляции и wall clock по точкам;
- пройденное расстояние, расход батареи и столкновения по телеметрии судьи;
- причину отказа и подтверждение остановки.

Успех означает достижение всех точек в допуске; столкновения записываются
отдельной метрикой. Суммарные показатели включают ожидание HTTP между точками и
остановку. Сравнивайте расход и время вместе с успехом и количеством выполненных
точек: короткий неуспешный маршрут нельзя считать более эффективным. `hard`
содержит события по времени симуляции, поэтому разная скорость движения может
привести к разным наблюдаемым условиям при одинаковом seed. Для первоначального
сравнения используйте статический `easy`, затем несколько фиксированных seeds.
Один маршрут — smoke-проверка, а не статистическое доказательство превосходства.

Существующий файл результата не перезаписывается. Код выхода: `0` — оба
запрошенных прогона успешны, `1` — runtime ошибка/отказ, `2` — неверные аргументы.
Скрипт оставляет стенд остановленным на последнем выбранном backend.

Проверки самого harness выполняются без ROS, Docker, сети и модели:

```bash
python3 -m unittest discover -s scripts -p 'test_compare_navigation.py'
```
